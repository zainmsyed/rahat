## Summary

The story-008 implementation adds a Google Calendar onboarding step, backend status/disconnect endpoints, and an OAuth callback route. The code is functional and tests pass, but there are a few low-severity simplification items, a medium test gap, and one copy bug.

## Findings

### 1. Duplicated API base URL configuration in callback page

- **Severity:** low
- **Category:** simplification
- **Summary:** The OAuth callback page redefines `apiBaseUrl` locally instead of importing it from `$lib/api/onboarding.ts`, creating a second source of truth for the backend URL.
- **Evidence:** `web/src/routes/onboarding/calendar/callback/+page.svelte` line ~11: `const apiBaseUrl = import.meta.env.VITE_API_BASE_URL || 'http://localhost:8080';`
- **Recommendation:** Export `apiBaseUrl` from `onboarding.ts` (or a shared API config module) and import it in the callback page.
- **Rule candidate:** Keep API base URL configuration in a single exported constant.

### 2. Missing frontend tests for new pages

- **Severity:** medium
- **Category:** test-gap
- **Summary:** The new calendar step and OAuth callback pages have no unit/page tests. Existing review and telegram pages have at least basic tests.
- **Evidence:** New files `web/src/routes/onboarding/calendar/+page.svelte` and `web/src/routes/onboarding/calendar/callback/+page.svelte` have no accompanying `.test.ts` files.
- **Recommendation:** Add minimal page tests covering unavailable state, connected state, and callback error/success handling (mocking `fetch` for the callback).
- **Rule candidate:** New route components should include at least a smoke test.

### 3. State endpoint's calendar_connected true path not covered by handler test

- **Severity:** low
- **Category:** test-gap
- **Summary:** Backend tests verify `calendar_connected` is false after disconnect and that the service reports connected, but no handler test asserts the state endpoint returns `calendar_connected: true` when a connection exists.
- **Evidence:** `cmd/server/onboarding_test.go` has `TestOnboardingCalendarDisconnect` checking false; service tests check true; no state-endpoint true case.
- **Recommendation:** Add a test that seeds a connection, calls `/onboarding/state`, and asserts `calendar_connected` is true.
- **Rule candidate:** —

### 4. Hardcoded step numbers in page templates

- **Severity:** low
- **Category:** simplification
- **Summary:** Each onboarding page hardcodes its "Step N" label, which is now brittle after inserting the calendar step. The stepper already derives step numbers from the steps array.
- **Evidence:** `web/src/routes/onboarding/calendar/+page.svelte` "Step 4 · Recommended", `tasks/+page.svelte` "Step 5 · Required`, etc.
- **Recommendation:** Derive the label from the step object (e.g., `Step {steps[3].id + 1}`) or remove the hardcoded label in favor of the stepper.
- **Rule candidate:** Derive step labels from the canonical steps array.

### 5. OAuth state row proliferation on repeated calendar page loads

- **Severity:** low
- **Category:** simplification
- **Summary:** Every time a not-yet-connected user loads the calendar step, `handleCalendarStatus` generates a new OAuth state row. Unconsumed states expire after 15 minutes, but repeated refreshes create unnecessary rows.
- **Evidence:** `cmd/server/onboarding.go` `handleCalendarStatus` calls `calendarService.GoogleAuthURL` unconditionally when not connected.
- **Recommendation:** Consider returning a cached/reusable pending state for the same user/session until it is consumed or expires.
- **Rule candidate:** —

### 6. Review page promises a settings page that does not exist

- **Severity:** low
- **Category:** bug
- **Summary:** When calendar is not connected, the review page tells the user "You can connect it later from settings." No settings page/route exists yet.
- **Evidence:** `web/src/routes/onboarding/review/+page.svelte`: "You skipped the calendar step or it was not available. You can connect it later from settings."
- **Recommendation:** Change copy to avoid referencing settings until it exists, e.g., "You can connect it later once settings are available."
- **Rule candidate:** —
