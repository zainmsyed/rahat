## Findings
### Finding 1
- Severity: high
- Category: bug
- Summary: Google OAuth account linking is not bound to the user who initiated the flow, so a valid OAuth code can be attached to any Rahat user ID.
- Evidence: `internal/calendar/service.go` generates the Google auth URL with `state=userID` via `GoogleAuthURL`, but `cmd/server/main.go` accepts `POST /calendar/google/connect?user_id=...&code=...` and `calendar.Service.ConnectGoogle` only exchanges the code for whatever `user_id` is supplied. The returned `state` is never verified and no nonce/session binding is stored.
- Recommendation: Persist an OAuth state token (or signed state payload) when generating the auth URL, then require and verify that returned state before exchanging the code and storing tokens. Add a test that rejects mismatched or missing state.
- Rule candidate: OAuth account-link flows must verify the returned state against stored initiation context before exchanging the code or binding tokens to a local user.

### Finding 2
- Severity: medium
- Category: bug
- Summary: Any single large calendar event activates day-wide small-task-only filtering, even when the large event blocks only one window.
- Evidence: In `internal/scheduler/service.go`, `buildCalendarConstraints` appends every `large` block title to `largeTitles` and sets `SmallTaskOnlyReason` whenever `len(largeTitles) > 0`. Later, `fitCandidates` defers every task longer than 15 minutes whenever `SmallTaskOnlyReason != ""`. That means one six-hour evening event would restrict the entire day, not just the affected window. Existing tests cover only all-day large events (`seedAllDayCalendarBlock`) and do not catch this narrower-window case.
- Recommendation: Limit small-task-only mode to true large-day conditions (for example all-day events or explicitly cumulative full-day coverage), and add a regression test for a single-window large event that should not constrain unrelated windows.
- Rule candidate: When a rule is intended for whole-day constraints, do not trigger it from a single-window event unless the implementation explicitly proves full-day coverage.
